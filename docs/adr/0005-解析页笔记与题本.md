# ADR 0005 — 解析页可记笔记，做笔记即收录进「补充题本」

- 状态：Accepted（2026-10-06 用户逐条批准本票全部决策；2026-10-07 用户改判**成员口径**与**界面形态**，
  决策 8 / 9 / 13 / 15 就地修订，新增决策 32-34；2026-10-08 再改一次界面形态与名字——
  界面名改成**补充题本**，笔记搬到内框外那一栏；同一天用户又改一次摊法（决策 15 第三版：
  一页 20 题 + 内滚 + 解析默认收起）、并改判笔记浮窗的键面与两态（决策 26 第三版），
  新增决策 35「笔记编辑区只有一份」；**同日第二次**：题本对齐错题页那一屏（决策 15 就地再修订、36 新增），
  「补齐题面」与「与站点核对」改成自动（决策 33 / 34 / 37 就地修订）；
  **同日第三次**：用户回看后要求筛选按"克制"的口径留回三档、三颗维护键合成一颗（决策 9 / 15 / 24 再修订、
  38 / 39 新增））
- 日期：2026-10-06
- 取代：ADR 0003 决策 1、2、4（其中决策 1 的前提被实测证伪，见下面「背景」第三条）
- 实现：ADR 0002 的决策 1（笔记按题目 ID 全局唯一）与决策 2（做笔记即收录）

## 背景

笔记原来只在站点那两个列表上能写（错题页 / 收藏页）。而真正想记的时刻在交卷之后：
专项练完一套、模考出完成绩，逐题看解析的那一遍。站点侧这两批题都不进错题接口（模考成绩不进、
专项的答错也不进），答对的题更是根本没有入口，所以「想记一笔」必须先跑到错题本或收藏夹，
而那里根本不存在这一题。用户 2026-10-06 定下这一轮要做的事：进入解析界面即可记笔记，
不限错题或收藏；记下的题在助手里有自己的区域，按站点错题本那样摊开题面与解析。

页面形状是 curl 公开模板实测出来的（模板文件在本仓库外，字节数可复算）：

1. **`zhuanxiang.html` 同时是答题页和解析页**。同一份 `zhuanxiang/dati.template.html`（29156 字节）里
   交卷按钮与倒计时挂 `ng-if="!isAlreadySubmit"`，解析块 `.analysis` 挂 `ng-if="isAlreadySubmit && isViewAnalysis"`。
   于是「@match 不含做题页」这条按文件名划界的做法在这一页**结构上做不到**，闸门只能按状态划。
2. `practice.html` 的 `practice/dati.template.html` 71038 字节里 `analysis` 出现 **0 次**，
   `dati.html`（接口无解析、无正确答案，ADR 0003 记录）——这两个文件上没有「解析界面」这回事。
   （它们与考试 / 练习两种模式的对应关系另有一处待裁定，本票不拿它当前提。）
3. 还有第三类解析页 `analysis.html`（路由 `#/`、`#/result`、`#/rank`，用 `analysis/analysis.template.html`
   11893 字节，**整分区一次摊开** `.question-outer`/`.inner-content`），入口是全真与大赛交卷后的跳转。
   ADR 0003 决策 4 那套「内联挂载」当年就是替它写的，随机考助手于 2026-10-03 删除一起没了实现对象。
4. 专项解析页每题的 scope 上 `content / material / opt(o.label,o.content) / analysis / correct_answer /
   user_answer / id / is_favorite` 全在（模板绑定为证，`{{subjectObj.correct_answer.join(',')}}` 等）——
   抓一份完整题面快照**零额外请求**。同页也有站点自己的 `is_favorite` 收藏。

## 决策

1. **作用域：解析页笔记只做专项练习页（`zhuanxiang.html` 交卷后）**。
   2026-10-06 一度扩到模考报告页与 `analysis.html`，**10-07 由用户下令全部撤回**：那两页的题目节点
   与数据形状各不相同（模考页是 swiper 一屏一题、列表态 scope 没有题干；`analysis.html` 是整分区摊题），
   为它们一再加白名单的同时，也加进了一处持续吃内存的循环（见下面「后果」）。
   现在的边界是：**逐题小条与笔记浮窗只长在专项页上**；模考报告页仍只有「模考收录」那颗浮标（那是
   1.10 就发出去的功能，不属于本票）；`analysis.html` 一行 `@match` 都没有，**别再往里加**。
   `practice.html` / `dati.html` / `guide.html` 继续零注入——实测那两页根本没有解析数据。
2. **闸门按交卷状态判，不按文件名划界**（`zhuanxiang.html` 上文件名划界结构上做不到）。
   交卷态的信号是 URL 查询带 `status=finished` 且 `submit_id` 非空、scope 上 `isAlreadySubmit` 为真；
   两道都成立才注入，判不准时只在控制台 warn 并写明缺哪一道，界面上零痕迹（fail-closed，无逃生阀）。
   **解析容器在不在不是闸门条件**，它只决定「解析区能不能划、`analysis` 能不能补」——两级分工见决策 20。
   ADR 0003 决策 3（「考试中翻自己笔记」明确放弃）继续维持。
3. **能力面**：解析页给「笔记 + 划线 / 批注」全套。划线那条不是顺手加的——「写过笔记**或**有任一条划线的题
   都算进列表」是既有口径，而解析区划线正是笔记素材的主要来源；只给文本框会把同一个「素材→笔记」闭环
   拆成两个界面各做一遍。不给页边批注轨道（zhuanxiang 的 `.question-box` 是 `position:fixed;overflow:scroll`
   且一屏一题，那套「可视区右缘 − 落点」的几何要重推）。
4. **同一份脚本、同一个存储键**：并进错题助手（`gongan_tiku_helper_<ctx>`），不起第三份脚本——
   笔记按题目 ID 全局唯一这条一旦分键就要做跨键同步，比省下的行数贵。
   **发布纪律**：真页面端到端跑通之前不上架 8111（商店是推送式更新，装着的人没有「先不升」的选项，见 ADR 0001）。
5. **存储形状**：新增只增桶 `store.snaps[qid] = {content, material, opt, correct_answer, analysis,
   content_type, module, from, at}`。`mockQs` 不动、其「模考收录」语义不稀释。取题面按
   `snaps → mockQs → 当前页 scope 项` 的次序；同一 id 在 `snaps` 与 `mockQs` 里内容不一致时 `warn` 不自动改写
   （沿用 ADR 0004「不替用户决定哪一份是真的」）。**快照齐不齐是三态不是二元**（10-07 补）：
   `snapState()` 返回 `full`（题面与解析都在）/ `part`（残缺：有题面没解析正文）/ `none`（没快照）。
   旧库缺 `snaps` 的降级：题本里显示 240 字题干引文 + 补全提示，不报错、不迁移；残缺的那批单独说一句，
   因为「有快照」不等于「摊得出解析」。两者都由决策 33 那颗「补齐题面」补。
6. **多标签合并**：`mergeConcurrent` 给 `snaps` 开一条并集通路——题面**先到先得**（后来的没有信息量），
   但 `analysis` 从空串变非空要补上：站点收起解析时 `item.analysis` 是空串（正文转入 `analysis_shadow`），
   「先到先得」若一路走到底会把题面永久钉成没有解析的那一份。
7. **取集范围与体积**：只为「写过笔记或有划线的题」和「模考收录题」存快照——这两类都是用户自己动过手的集合，
   脚本不替他囤题。不设条数上限、不裁剪、不自动删；`saveStore()` 写失败时把错误原样报出来，
   提示先「备份全部数据」再清理。不做「丢掉某题解析正文只留题面」那种手动体积阀：删谁都是替用户做决定。
8. **旧笔记回填只在取题那一路**：`backfillSnaps` 挂在 `fetchByFilter` 上（重练取题与「与站点核对」共用它），
   只增不覆盖，且**只补已在名单里的 id**（写过笔记或有划线的）——回填范围与决策 27 同一条口径。
   本条原写「错题页 / 收藏页每次渲染题目时顺手补」，**实现从未落在那条路上**（`injectListUI` 只登记引用表），
   10-07 复核后按实际形状改写，并明确**不做**渲染即回填：决策 15 改了成员口径之后，站点在列的题根本不进题本，
   渲染时回填出来的那批快照没有消费者，只是替用户囤题。没有快照的题仍进题本，按决策 5 的降级显示。
9. **界面：题本是一块与「机考助手」同级的独立视图**（10-07 由用户改判，原写「助手视图加第四个 tab」）：
   左菜单在「机考助手」下面再加一颗「补充题本」，打开时与助手视图互斥，两块共用同一处收起站点内容的逻辑
   （`applyChrome`）与同一个状态栏写入点。笔记在页边那一栏（`.gth-rail` 里那张 `.gth-aside`），
   不在视图内另开面板。
   ~~代价当场说清：同一道题从此有两个入口、两套筛选状态，所以两者之间要能互相定位。~~
   **10-08 第三、四次修订**：先按用户口径把题本这侧的筛选整个撤掉（决策 24 那条随之作废），
   当天又改判留回三档（决策 38）——所以"两套筛选状态不共享"这个代价**部分回来了**：
   题本有科目 / 模块 / 关键词，笔记那一屏有自己的五档，两边不共享，
   因此笔记 → 题本那颗跳转（`jumpToBook`）仍是必需的，题本 → 笔记那颗（「在笔记里定位」）撤掉了。
10. **来源长出第四档**，界面上叫「题本」：导出单选与重练勾选都要有它，`SRC_KEYS` / `SRC_NAME` /
    `EXPORT_PREFIX` 三处一处不能漏（少了前缀 `runExport` 会静默落默认前缀，用户在下载目录里认不出这批）。
11. **术语上位**：「来源」退回**站点侧两档**（错题本 / 收藏夹）+ **本地两档**（模考收录 / 题本）。
    「收录」这个词从此指动作（把题面与快照存进本地），不再单独当作「模考收录」的简称。
12. **一张卡片一个渲染器**：题本与重练报告共用一个卡片渲染器（`questionCardHtml(q, opts)`），
    各块**允许缺席**——重练报告那条按答对 / 答错 / 未做换色的描边与「你的答案」行，在题本里那道题
    可能从没答过（错题本档也没有单题作答记录，只有「能进错题本就算错过一次」）。
    类名继续走 `gthq-`，**不抄站点类名**：宿主页面挂着 bootstrap 3.3.7 / normalize / font-awesome 4.7
    三套全局样式，抄短名字就是等着被别人的规则画上去。
    抽公共渲染器这一刀**必须配接线判据**（T20 那一类）：只测新函数、不测「重练报告那处真的改成调它了」等于没守。
13. **解析页只做逐题小条，不重建视图**：`zhuanxiang.html` 与模考报告页上给每题挂一条 `.gth-qbar`
    （笔记 / 复制题目 / 划线数 / 收录标记），点开就地编辑；**题本只长在 `index.html`，形态是与助手视图
    同级的独立一块**（决策 9）。
    实测 `mocks/index.html` 外壳与 `mocks.min.e084c274.js`（106428 字节）里 `left-menu` /
    `gongan2-container` / `right-content` 计数**全为 0**，只有一个 `ng-view`——视图那套挂载点在这一页
    结构上不存在；而题本的筛选条、组卷、导出、徽标全长在视图里，重建一次就是让
    `syncFilterUI` / `readFilter` / `renderNoteFilterMods` 在第二个容器里再活一遍。
14. **快照抓取时机 = 动作即抓**：`setNote()` 与 `addHighlight()` 那一刻从当前页 scope 项抓快照，
    四个界面（错题页 / 收藏页 / 专项解析页 / 模考报告页）共用一条 `harvestSnapshot(item, from)`。
    不做「每次渲染扫一遍列表全抓」（那违背决策 7 的不囤题）；也不做「只有写笔记才抓」
    （那会让只划线没写字的那批题——按既有口径它们要进列表——全成降级卡片）。
    解析块还没展开时 `analysis` 允许先存空串、日后按决策 6 补；**脚本不替用户点站点的「查看解析」**。
15. **题本的摊法与成员**：**一页 20 题 + 底部分页器**（`« ‹ 1 2 3 … N › »`，与站点错题页同一个形状；
    2026-10-08 用户第二次改判：先是「一次摊 20 题 + 加载更多」，再改成「一页一道题 + 分页器」，
    最后定在**一页 20 题、中间那列自带内滚、翻页器在盒子外面**——用户的原话是
    「中间区域只显示题目，带内部滑动栏，…一页显示20题，保证翻页功能正常，去除搜索，
    体验应该和行测、公专等错题界面一致」。内滚盒高度 `min(600px,calc(100vh - 300px))`，
    站点错题页那份 `.content` 是死写的 `600px`。
    **10-08 第四次改判：整张卡片照错题页那一屏重做**（用户原话「题目头部就这么几条信息，保持其功能一致，
    解析展开在右下角，请你尽量模仿原界面的UI设计，不要有多余功能，不要加任何筛选」）——
    头部就是错题页那行小条（答错次数 / 掌握状态 / 笔记 / 复制题目），
    **科目、模块、模考收录三枚标签与「x 天前动过」全部撤掉**，卡片底部那三颗按钮也撤掉；
    题号是站点那个 25px 淡蓝方块，序号按整本连续折算（`(页-1)×20 + 序`，与站点模板里
    `(currentPage-1)*itemsPerPage + $index + 1` 同一个算法）；
    选项靠圆圈上色（正确绿、错选红），**不再在文字后追「（正确）」、也不给整行上色**；
    解析展开是右下角那条线（1px `#ddd` 拉满 + 「展开／收起 查看解析」+ 10px 三角），默认收起；
    卡片自身不带外框与左色条（原来复用重练报告的 `.gthq-r-item` 才带来的），
    题与题之间只靠那条线分隔——错题页就是这个样子。
    **筛选只留三档**（同日第五次改判，见决策 38）：科目、模块、关键词。
    **笔记写在内框外那一栏**（页边批注栏 `.gth-rail`，
    与错题页同一张 `.gth-aside` 卡片、同一套绑点），不是视图内另开一块面板——
    用户 10-08 的原话是「笔记的位置应该在红色框出的地方，和错题本内显示的一致」；
    这一页摊几道题，那一栏就摆几张批注卡，位置由 `placeRailItems()` 按卡片此刻的视口位置算。
    成员是**派生集合**：（写过笔记 ∪ 有划线 ∪ 模考收录）**减去站点此刻还收着的那些**（决策 32）。
    10-07 由用户改判，原口径是「笔记 ∪ 划线 ∪ 模考收录」全收——那与站点自己的错题本重复；
    题本存在的理由要说成「让记了笔记却没错、没收藏的题有去处」才对得上界面给人的感觉。
    ~~**没与站点核对过一次就一条都不摊**：那一刻「站点没有」这个判断本身还没成立，宁可空着并说明原因，~~
    **10-08 改判：核对也不再要用户点**（决策 37）——摊开错题页或收藏页就自动跑一次，
    题本空态那句改成「正在与站点核对，跑完自己摊开」，等的是几十秒而不是一次点击。
    **不做「移出题本」这个开关**——
    一旦允许「移出题本但笔记还在」，`snaps` 就变成第三个由用户手维护的名单，和笔记、划线两个来源随时打架
    （同一题在笔记 tab 里还在、题本里没了，没人记得为什么）。要让一道题离开题本：删掉它的笔记与划线，
    或者让站点把它收进错题本 / 收藏夹——下一次核对当场带走。
16. **第四档的接法**：取题从 `snaps` + `mockQs` 本地读，零请求；导出下拉与重练勾选各加一项（界面名「补充题本」，内部来源值仍是 `book`）；
    它与错题本 / 收藏夹**并列可勾**，同一题跨档出现时按 id 去重（`dedupeById` 已有）；
    「两者合并」继续只指错题本 + 收藏夹，不与题本组合出第五种。「模考收录」这个名字**不改**：
    它牵动 `SRC_NAME.mock` / `EXPORT_PREFIX.mock` / 笔记来源下拉，以及续刷键里那句字面量
    `模考收录（全部模考题）|asc`，而 ADR 0004 的键代归因与自愈正靠这些名字认代。
17. **同 id 两份题面时**：题本里显示**一条**，取 `snaps` 那份，卡片上标「与模考收录的题面不一致，请核对」。
    不引入合成 id（`m + examId + '_' + qid` 那一类只在「键相同而内容不同」成为常态时才付得起），
    也不静默取一（那是替用户决定哪一份是真的，ADR 0004 明令不许）。
18. **与「考试计时暂停」的关系**：不互检测、不合并。计时那份在交卷后自己走 `isAlreadySubmit` 分支摘掉按钮，
    两份的时间窗不重叠；靠 window 上挂暗号互探是「谁先加载都可能出错」的脆弱耦合，
    合并则让错题助手每次更新都可能改动考试中的计时行为。**留一条 L2 待测**：同页并存时，
    计时那份给 scope 时间字段装的 getter/setter 阀门不影响错题助手读题面字段。
19. **实施顺序（三步，每步有当场可核的变化）**：
    ① `snaps` 桶 + 公共卡片渲染器 + 题本 tab + 错题页/收藏页回填——完全不碰新页面，四条命令与本机夹具就能验；
    ② `zhuanxiang.html` 的交卷态闸门与逐题小条（笔记 + 划线）；
    ③ 模考报告页的逐题小条 + 拆掉 `initMocksUI()` 之后那个 `return`。
20. **闸门是两级，不是一道合取（本条就地修正决策 2）**：决策 2 原写「三道信号全中才注入」，
    但解析块挂的是 `ng-if="isAlreadySubmit && isViewAnalysis"`——**用户不点「查看解析」时解析容器根本不存在**，
    拿它当闸门条件就等于把「刚交卷、想先记一笔」这个最顺手的时刻挡在门外（而那一秒恰恰是本票要解决的事）。
    改成两级：**交卷态两信号**（URL `status=finished` 且 `submit_id` 非空 + scope `isAlreadySubmit`）成立
    就挂逐题小条——笔记、题干与选项的划线、题面快照全部可用；**解析块展开只额外解锁**「解析区划线」与
    `analysis` 字段的补全。这样安全是因为代码本来就兜住了：`paintRoot` 在解析不在 DOM 时走 `hlHoldLost`
    **不落笔也不累计 `miss`**，`repaintHighlights` 只遍历还在的 `[data-gth-qid]` 节点，
    所以切题时被 `ng-if` 摘掉的整题不会被误判成划线失效。
21. **不做逃生阀**：站点哪天改掉 `status` / `submit_id` 或不再给 `isAlreadySubmit`，症状是「这页没有笔记入口」
    （fail-closed、可用），不加 URL 参数或控制台开关绕闸门；取而代之的是 warn 里写清缺的是哪一道信号。
22. **`from` 存而不显示**：`snaps.from` 取 `error` / `favorite` / `zy`（专项解析页）/ `mock`，
    记录「抓快照那一刻人在哪一页」，只留作诊断证据。**界面上「来源」一词只指那四档**
    （错题本 / 收藏夹 / 模考收录 / 题本），再造第二条同名筛选条就是把「抓取痕迹」和「集合归属」混进一个词。
    逐题小条上那颗标记的措辞定为**「已收录」**（动作结果），不叫「在题本」（那是区域名）。

    所以留回三档（科目 / 模块 / 关键词）。这条否决**仍然成立的部分**是：
    不做「用当前筛选结果开一轮重练」的直达，也不做单题重练。

    且只清「既无笔记也无划线的快照」——不放卡片上，否则又变成一个跟派生口径打架的手维护开关。

31. ~~**孤儿快照清理是「本地数据」里独立的一行 + 独立的确认框**，不并入「清理残留」：

32. **`harvestSnapshot` 按候选键取值，取不到题面就不建快照**：运行时 scope 的字段名到本轮为止

    所以取值沿用 `MOCK_*_KEYS` 那套候选键 + `pickKey` 的写法，而不是照模板写死一个名字；
    认不出题面时只记笔记、不建快照，并在控制台写清缺哪几个字段（fail-soft，不写坏数据）。
    运行时形状的一次真页面探针（只读）随时可补进来，它证的是这一整条链的承重墙。

32. **`store.qSrc` 从「只增的来源记录」改成「可失效的站点在列缓存」**（10-07）：每次「与站点核对」跑完
    全量之后，这一趟没见到的 id 一律剪掉；**没跑全时只并不清**（按日期那一趟撞到翻页上限就属于没跑全，
    上限与 `pagedFetch` 的翻页闸门配着看，改一边不改另一边会把没跑全的一趟当成全量去剪名单）。

    否则这边剪掉、那边一保存又并回来。它因此是缓存不是用户数据：删它不丢东西，下一次核对自动重建。
33. **题本「补齐题面」是自动的**（10-08 第二次修订就地改：原来是一颗按钮加一个问号说明，
    用户口径「补充题面不应该让用户手动操作，应该自动化实现」）：
    按题目 ID 打站点那道题的解析接口（`api/v2/tiku/{examType}/{id}/analysis`，
    与模考收录逐题补题面同一条路，地址只留一处出处 `apiSubjectFace`）。只补 `snapState() !== 'full'` 的成员，
    一题一个请求、题间隔 180ms、一轮上限 300 题、进度写状态栏。`examType` 先认笔记上记过的科目（只认 0 与 1），
    认不出就行测与公专各试一次。这一条是新成员口径（决策 15）的**必备件**：题本剩下的成员恰好是
    站点两个列表回填够不到的那批，没有这条路它们永远只有 240 字题干引文。

    用户正看着的那 20 题不该排在别人后面。

    按钮撤掉之后这条链没有第二次入口，所以 `autoFillFaces` 的接线判据（`renderBookList` 真的调它）
    是这条能力唯一的守卫——删掉那句调用，界面上一切照常，只是缺题面的题永远缺着。
34. **卡片提示的措辞跟着能力走**：缺题面与缺解析各说一句，且**不许指挥用户动作**（10-08 就地修订：
    原来两句都写「点『补齐题面』」，那颗按钮撤掉之后就成了指向不存在入口的假承诺）。
    现在写「正在自动向站点要」「正在自动再要一次」。
    更早那句「在错题页、收藏页或解析页摊开一次，脚本会顺手补上」是一条**没实现过的承诺**（见决策 8），撤掉。
35. **笔记编辑区只有一份**（10-08）：`noteAreaHtml` / `bindNoteArea` / `bindNoteAreas` 三件，

36. **题本头部与错题页那行小条是同一个东西**（10-08）：同一套类名（`.gth-qbar` / `.gth-err` /
    `.gth-badge` / `.gth-qbar-note` / `.gth-qbar-copy`）、同一份刷新（`refreshBadges()` 遍历 `.gth-qbar`）、
    同一份绑定（`bindQbar(bar, itemOf)`，取题面的函数由调用方给，两边数据源不搅在一起）。
    错题页那行小条**不是站点原生的**——站点在每题上只画题号方块与右下角那条「展开 查看解析」，
    这四颗是本脚本注入的（`injectListUI`）。所以"题本对齐错题页"对齐的是我们自己的那一行，
    这条决定把它从"抄两遍"改成"共用一份"。
    题本里点「笔记」**不再关掉题本**：那一栏的批注卡本来就在这一块视图右边，
    但同一张卡可能同时挂着错题页那一张（站点内容只是藏起来没拆），所以按 `data-book="1"` 认自己那张。
37. **与站点核对自动跑一次，且只跑一次**（10-08）：摊开错题页或收藏页就调 `autoReconcile()`，
    题本空态那一路也调（题本开着时 `injectListUI` 会早退，少一条就是题本永远停在「正在核对」）。
    `reconcileTried` 让它**失败也不重试**——这条调用挂在 400ms 观察器的射程里，
    失败就重试等于每半秒打一遍站点接口。手动那颗键仍然留在助手视图·本地数据那块，失败时用户还能点。
    这一条不改成员口径（决策 32 的「没核对过就没有题本成员」照旧），只改**由谁触发**。
38. **题本顶部留三档筛选**（10-08 同日第五次改判，撤销「不要加任何筛选」那一版）：
    用户原话「补充题本应该在顶部加上和行测、公专一样，加上顶部的科目类型筛选与搜索等，
    但筛选条件保持克制，从用户角度充分考虑，你到底至少需要哪些筛选条件即可满足需求」。
    倒推「打开题本想干什么」定下三档：**科目**（站点错题页顶部本来就有这两颗标签，切科是肌肉记忆）、
    **模块**（行测复盘的主轴，用户点名要）、**关键词**（题一多就找不到，这是唯一"找题"的入口）。
    **明确不要的三档**：来源（笔记题 / 模考收录——用户不关心题从哪来）、掌握状态（笔记那一屏已有）、
    快照齐不齐（内部概念，摆出来只会让人猜它是什么意思）。
    实现上三条硬约束：关键词要读题面，比另两档贵，**只在真输了字时才跑**；匹配前先 `stripHtml`
    （题面是 HTML，不剥的话搜一个「p」命中每一题）；输入框带 debounce，否则每敲一键重主题本 + 重画页边那一栏。
    「清空筛选」只在真筛了的时候露出，筛到空的那一屏也画同一颗出口——留一颗永远灰的键就是骗人。
39. **「升级后点我」合成一颗键**（10-08，用户口径「不要给没有互联网基础的用户加认知负担导致他们不敢点击」）：
    原来那三颗（与站点核对 / 清理残留 / 清孤儿快照）没有一张脸能让人看懂，于是没人敢点，
    而其中「与站点核对」是题本成员口径的前置件——不点就等于题本永远空着。
    现在一颗绿色键一次点完：先 `upgradeScan()` 把要删的三份扫齐 → 有东西就**列清单弹一次确认** →
    删完接着 `reconcileWithSite`。无东西可删时不弹空框，直接核对。
    **这条不推翻「不自动删任何东西」**（决策 7 与 `saveStore` 那条）：压掉的只是追问的**次数**（三次变一次），
    不是追问本身。合并入口若顺手做成静默删，就是替用户做决定——那是另一回事。
    问号 `title` 里给人话说明，键面只五个字。

## 否决的选项

- **复用 `mockQs` 一桶装所有快照**（加个 `from` 字段）：省一张表，但 `mockToList` / `mockModuleOptions` /
  导出前缀 / 笔记来源判定全要跟着改，「模考收录」这个词被稀释成「一切本地题」。
- **快照嵌进 `store.notes[qid]`**：无笔记、只有划线的题就没有快照，而那一类题按既有口径要进列表。
- **第三份脚本 + 独立键**：2026-10-03 刚把这条路上一次尝试删掉（ADR 0001 的作废条款就是它的尸体）。
- **解析页只给笔记文本框**：见决策 3。
- **把新区域并进「笔记」tab（原地摊开完整卡片）**：只有一份列表、一套筛选，最省，代价是笔记 tab 变成
  几十屏的长页面；用户 2026-10-06 选择加第四个 tab，10-07 又把它挪出去做成同级视图（决策 9）。
- **渲染时顺手回填**（决策 8 的原字面）：新成员口径（决策 15）之下，站点在列的题根本不进题本，
  渲染时抓回来的那批快照没有消费者，只是替用户囤题——违背决策 7。
- **装完脚本自动跑一次全量核对**：几十秒级异步、没有任何用户动作就往站点发几百个请求，
  与「取题与组卷是几十秒级异步，按钮必须置灰」这条既有规矩相反；改成空态 + 一颗「与站点核对」。

## 后果

- **10-07 二次改判的形状**：题本从助手视图的第四个 tab 变成左菜单里与「机考助手」同级的一块独立视图，
   两块互斥、共用同一处壳收放（`applyChrome`）与同一个状态栏写入点。成员口径同时收窄成
   「动过笔或模考收录，**且站点此刻没收着**」，没核对过就空着。
