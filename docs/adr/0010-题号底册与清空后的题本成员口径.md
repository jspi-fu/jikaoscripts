# ADR 0010 — 题号底册：站点清空错题本之后，题本成员按"本机见过"算

- 状态：Accepted（2026-10-14 用户批准，六问各按建议定）
- 日期：2026-10-14
- 相关：`docs/adr/0005` 决策 15 与 32（题本成员口径的旧写法）、`docs/adr/0004`（存储只增）、
  `CONTEXT.md`「题号底册」「补充题本」「站点在列」「题面快照」

## 背景（全部是 2026-10-14 在用户登录态上只读 GET 实测的）

站点把错题本清空了，题目本体还在。

- `content/{contentId}/error/view` 对 content_id **1–8 全部** `code=0 total=0`；
  `api/v2/tiku/{T}/error/statis` 的 `label_list` 是 null（T 试了 0/1/5/1620/1621）。
- 题面按 ID 仍拿得到：`api/v2/tiku/0/1848797/analysis`、`2453070`、`3373429` 三个旧题号都
  `code=0` 带回完整题干；快照里那 44 枚图片 URL 实测 200
  （`img.xdtech.top/uploadFiles/…`、`xdtest.xdtech.top/test/admin/webupload/…png`）。
- 专项练习页照常渲染（行测的政治理论 / 常识判断 / 言语理解 / 数量关系 / 判断推理都在），
  站点 bundle `core.min.07665c98.js` 里 `error_list` 那条路径一字未改——**不是前端藏了，是数据侧空了**。
- 收藏还剩 1 题（id 3392686「亡羊:补牢」）。就因为它非空，`reconcileSources` 那台判成
  "这一趟跑全了"（`complete = siteList.length > 0 && < SITE_LIST_CAP`），把 `qSrc` 从 479 剪到 1。
- 各用户损毁程度不一样：错题与收藏**同时清零**的人 `siteList.length === 0` → `complete=false` →
  只并不剪，`qSrc` 反而整份保住；像这样只剩几题收藏的人会被剪。

所以"用户手里还剩什么"不能压在 `qSrc` 上。`qModule`（`rememberModule` 只写不清）与
`exported.*`（`markExported` 只加不减）都是只增的，它们和笔记、划线、组卷历史合起来，
才是这场清空之后仍然完整的那份账。

## 决策

1. **新增「题号底册」（`seenIds()`）**：本机替用户记下过账的每一个题目 ID——
   笔记 ∪ 划线 ∪ 模考收录 ∪ 站点在列 ∪ 登记过模块名的 ∪ 答错过次数的 ∪ 改过掌握状态的 ∪
   重练过的 ∪ 导出过的（`exported` 那五个来源各一档）∪ 组卷历史里出现过的（`history[].ids`）。
   它**只增不减**，且**不含 `snaps`**：孤儿快照的判定要拿底册当豁免表，把快照自己算进去就是自指，
   那一档永远扫不出东西。
2. **题本成员改为「底册 − 站点在列」**。减法一字不动：站点哪天把题收回去，它就该离开题本。
   `reconciled()` 那道门保留——没核对过一次时"站点没有"这个判断还不成立，一条都不摊。
3. **补齐题面的触发点不变**（摊开题本就自动排队列、当前页优先、每轮 300、间隔 180ms），
   只把队列来源从旧成员口径换成新口径。不给「升级后点我」再叠第四件事。
4. **孤儿快照判定改为「不在底册」**。这一条是决策 1 的配套：不改的话，找回来的纯错题题面
   （没笔记、没划线、不在模考收录里）会在下一次点「升级后点我」时被当残留删掉。
5. **不给剪枝加"骤减保护"**。两个理由：底册已经不依赖 `qSrc` 一份；反过来，剪枝正是找回生效的
   开关——把 `qSrc` 留着会让站点其实收回去了的题永远挡在题本外面。
6. **题本头部报「题面不齐 K 题」**（K 走现成的 `snapState() !== 'full'`，即"没有"与"残缺"两态合起来，
   正是补齐队列在追的那一批），补齐那一趟报「补回 N 题 / M 题没要回来 / 本轮到 300 题上限、
   还缺的自己排下一轮」。自动补齐是唯一一颗没有按钮的链路，看不见进度就等于没人知道它跑没跑完。
7. **捞不回来的题留在题本里走降级显示**（只有笔记引文那一行），不剔除。那些 ID 是用户唯一的凭据，
   剔掉等于替他判定"你没做过这道题"。

## 认下的代价

- 题本成员从"动过笔"扩到"本机见过"，一批用户从没碰过的题会涌进来（这台机器 479 题里只有 58 题
  写过笔记）。靠既有的三档筛选与一页 20 题的分页承担，不加第四档筛选。
- 旧说法「要让一道题离开题本，就删它的笔记与划线」不再成立——底册删不干净是**有意的**。
  `CONTEXT.md` 已就地改掉那句。
- 名单大时要跑几轮才补齐（每轮 300 题上限没动），且认不出科目的题要行测与公专各试一次，
  请求数最多翻倍。
