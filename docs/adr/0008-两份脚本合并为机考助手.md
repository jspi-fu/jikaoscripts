# ADR 0008 — 两份脚本合并为「上岸村机考助手」：交付一份文件，两半各自隔离

- 状态：Accepted
- 日期：2026-10-08
- 相关：`docs/adr/0006`（暂停只管倒计时，划界不动）、`docs/adr/0004`（存储契约）、`docs/adr/0007`（逐题用时的键与写者口径在本票里改判定）
- 取代：`docs/adr/0005` 决策 18（「不互检测、不合并」）；`docs/adr/0007` 决策 1 / 3 / 4 里"两份脚本"那层作用域

## 背景

2026-10-08 用户下令：把「错题助手」与「考试计时暂停」合并成一份脚本，统一命名「上岸村机考助手」。
要解决的是三件事，都不是审美：

1. **同源拷贝**。两份各自现算 `CTX`、各自实现一套「取页面真身」（助手 `window.angular || unsafeWindow.angular`，
   计时 `pageNg()` 三条回退），靠"改一处要同步另一处"这句叮嘱与一条跨文件判据维持。那是结构性风险，不是笔误风险。
2. **同一页两套注入**。`zhuanxiang.html` 上两份脚本并存，各插一段 `<style>`、各起一只定时器。
3. **交付面**。商店两条、改名要改两处、用户手里两条要么一起更新要么版本错位。

三条查证来的硬事实（2026-10-08，不是推测）：

- **元数据只能留一套，`@grant` 取助手那套**。计时靠 `@grant none`（不进脚本猫沙盒）取页面真身，助手带
  `GM_xmlhttpRequest` + `GM_addStyle`。按 `AGENTS.md` 的沙盒一节，只要 `@grant` 不是 `none` 就走 `createContext` 建沙盒——
  合并后**计时那半第一次在沙盒里跑**，靠 `pageNg()` 的 `unsafeWindow` 回退取页面对象。
  「全文件 `@grant none`」那条路被否：它要把助手的跨域收题改成页面 `fetch`，风险落在收题上。
- **一条 uncaught 异常会终止脚本里它之后的全部语句**。所以"两半放进同一个 IIFE 顺序执行"做不到隔离，
  必须各自成段、各自兜住。
- **判据是最贵的一笔**。守计时那半的 `T33` 是一整块按**整份文件全文**计数的断言（`countOf("'elapsed_time'") === 0` 这类），
  而助手里真的存在 `el.className = ''`、`classList.toggle` 这些 T33 明令禁止的形状。

## 决策

1. **一份文件**：`shangancun-exam-helper.user.js`，`@name 上岸村机考助手`，`@version 2.0.0`。
   `@match` 取两份并集（新增 `practice.html` 三条）；旧的 `shangancun-exam-timer-pause.user.js` 从仓库删除。
2. **`@grant` 取助手那套**（`GM_xmlhttpRequest` + `GM_addStyle`），`@connect pub.xdapi.top` 保留。
   计时那半的 `@grant none` 作废；它靠 `pageNg()` 的 `unsafeWindow` 回退在沙盒里取页面真身，
   诊断串里的「取页:」照旧记下走的是哪条。
3. **两半各自独立 IIFE，计时段排在文件最前面，各自由 `try/catch` 兜住**。
   `try` 放在 IIFE 体内、`'use strict'` 之后——指令序言必须是函数体第一句，挪进 `try` 会静默丢掉严格模式。
   判据守这个形状，其中一条是：计时段不引用助手那半的任何名字（`CTX` / `QTIME_KEY` 除外，见决策 5）。
4. **存储仍是两把键，不并库**：`gongan_tiku_helper_<ctx>`（助手整库）与 `gth_qtime_<ctx>`（逐题用时）各写各的。
   合并不等于并库——并库要迁移老数据，而用时那个每 5 秒落盘一次，塞进整库等于让「只增映射」的合并每次带上一个高频桶；
   `docs/adr/0004` 那个 store 是冻结契约，形状不该为合并而变。
5. **`CTX` 与 `QTIME_KEY` 两半各自现算**（两半不共享作用域，也就共享不了变量）。
   判据从"跨文件一字不差"改成"**同一份文件里两处定义一字不差**"——同一条纪律，现在在一份文件里就守得住。
6. **版本 2.0.0**。商店 8111 那份更新并改名；计时那条置为「已并入，请卸载」的提示（不下发可执行代码）。
   发布说明第一步是**先卸载旧的两条**：`@name` 一改，脚本猫很可能把它当成一个新脚本，三条并存就是三重注入。
   不在脚本里做"检测到旧脚本"的自检——`ADR 0005` 决策 18 已经否掉过靠 window 挂暗号互探那条路。
7. **助手那半在 `practice.html` 上零痕迹**：它所有界面都按路由与交卷态划界，那一页不建任何 `.gth-` 节点（夹具守着）。
   计时那半仍按 `freezablePage()` 划界：`zhuanxiang.html` 有宿主即生效，`practice.html` 只在 `page_type=random`。
8. **计时段内与助手那半同名的 5 个名字加 `timer` 前缀**：`pad2` / `isZyPage` / `icon` / `LUCIDE` / `store`
   → `timerPad2` / `timerIsZyPage` / `timerIcon` / `TIMER_ICONS` / `timerStore`。
   最后那个是必须的：助手的 `store` 是整库对象，计时的 `store(v)` 是写暂停标志的函数——同名不同义，读的人一定会错。
9. **文件里放两行段落边界注释**（`// ===== 计时暂停…` 与 `// ===== 机考助手…`），判据按边界切片后在片内计数。
   这是"允许写注释"在判据层的配套口径，见 `AGENTS.md` 的代码风格一节。

## 后果

- `ADR 0005` 决策 18 拒绝合并的理由（"合并则让错题助手每次更新都可能改动考试中的计时行为"）**没有消失**，
  只是从"两份文件"降级为"两个 IIFE + 计时段前置 + 各自 try/catch"。隔离强度比以前弱一档，所以决策 3 里的判据不是装饰。
- 换来两样东西：同源拷贝消失（`CTX` 一字不差的跨文件纪律降为同文件内两处比对），`zhuanxiang.html` 上从两套注入变一套。
- `T33` 整块重写：文件名、切片、按整份文件计数的断言全部改到"计时段切片"上跑；
  `hit` / `miss` 也换到**剥注释后**的文本——不然注释里出现 `elapsed_time`、`operation-dati` 这类天然要解释的名字就会当场判红。
- 用户若没先卸载旧的两条就装新版，会出现三重注入；这一步只能写在发布说明里，脚本自己兜不了。
- 两半的判据合并进同一份 `tools/gth_logic_test.js`；`gth_init_order.js` 与 `gth_fixture.js` 的默认文件名改到新名。
- **待真页面证（L2）**：沙盒里 `pageNg()` 落到 `unsafeWindow` 之后，给 scope 装 getter/setter 阀门、读
  `localStorage.currentIndex` 是否与沙盒外一致；以及脚本猫把改名后的这份当作升级还是新装。
