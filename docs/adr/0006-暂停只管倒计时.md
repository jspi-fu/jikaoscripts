# ADR 0006 — 暂停只管倒计时：已用时间永不冻结，无后果的界面零痕迹

- 状态：Accepted
- 日期：2026-10-06
- 相关：`docs/adr/0003`（错题助手那一侧的划界）、`docs/adr/0005` 决策 13（交卷后那块头部归解析界面）

## 背景

「考试计时暂停」原本只有一档行为：按下之后把 `totalTime`、各板块 `remainTime`、`elapsed_time`、
`detail_elapsed_time` 全部装上阀门，站点每秒写进来的值被我们吞掉。于是「暂停」这个词同时背着两件事——
**倒计时停了** 与 **用时也停了**。

用户 2026-10-06 给出这份键要服务的两个场景，差别正好落在这两件事上：

- **练习时遇到急事**，暂时无法做题：**接受倒计时交卷，不需要知道真实用时**。
- **状态不好**，却为了不浪费倒计时被逼着蒙题、丢了做题质量：**不希望倒计时结束自动提交**，
  并且**需要知道真实用时**。

对着站点自己的公开静态 bundle 复算之后，几个前提变了（字节数与命中数都可重算）：

1. `zhuanxiang` 包（72485 字节）与 `practice` 包（81354 字节）里，`totalTime--` 与 `elapsed_time++`
   在**同一个 `$interval`** 内，同一段还带着 `currentPartData.elapsed_time++` 与 `detail_elapsed_time[...]`。
2. 这两包里 `Date.now` / `new Date` / `getTime(` / `serverTime` / `end_time` / `zeroDate` / `getCurrentTime`
   **全部 0 命中**——页面里没有任何"时刻"来源。冻住 `elapsed_time` 之后，界面上就**不存在**真实用时，
   除非脚本自己另设一只表。
3. 交卷上报给站点的正是 `elapsed_time:$scope.localStorage.elapsed_time`。**给它装阀门 = 往站点交一份
   少了一截的用时**，而这恰好是场景一说"不需要"、场景二明确"需要"的那个值。
4. 冻住 `totalTime` 让站点那条 `if(0==totalTime) → $interval.cancel(...)` 永不成立，于是那个 tick
   每秒照跑：不冻 `elapsed_time` 时，真实用时**由站点自己数出来**，脚本一个字节都不写。
5. 两个场景里"自动提交"这个后果并不在每个界面上都存在：practice 的**练习模式**是
   `totalTime>0?totalTime--:totalTime=0`，夹到 0 什么都不做，而且那一页头部显示的是
   「用时：x/总时长」而不是剩余时间；**只有考试模式**（URL 上 `page_type=random`）到点才交卷，
   并且板块 `remainTime` 到 0 会弹「系统将随机进入某个未作答部分」（`interval:!0` 自动关闭）
   把人随机扔进别的板块。`zhuanxiang` 的 `{{partTime}}` 那一行在模板里是注释掉的，没有跳板块这条路。

于是"两种模式"这个提法被拆掉了：两个场景要的是**同一个动作**，差别只在"要不要那份用时是真的"，
而那件事由第 3、4 条决定——它落在**哪个字段进阀门清单**上，不落在界面档位数上。

## 决策

1. **「暂停」只指冻住会被倒计时触发的后果**（整场倒计时 + 各板块剩余时间）。已用时间**不在**阀门清单里，
   永远由站点自己数，交上去的也是它。**明确放弃「净做题用时」**这个能力。
2. **不做两种模式，也不做"弱档"**。急事那一档不需要新代码：不按下就是它的结果（时钟照跑、到点交卷、
   用时真），而按下之后多出来的那份真实用时读数对场景一零伤害。给一个"尽力停、停不住就算了"的弱档，
   就是重新引入本仓库已经用判据堵掉的「兜底显示替功能说话」。
3. **划界按「这一页有没有会被倒计时触发的后果」**：`zhuanxiang.html` 有计时宿主即生效；
   `practice.html` 只在 `page_type=random` 生效。不生效的界面**零痕迹**——不注入 style 节点、不建键、
   不在站点节点上留 class，所以划界必须排在注入之前。`@match` 不动：两种 `page_type` 共用同一份文件。
4. **取消「不可暂停」那颗灰键**。停不住（找到计时器却装不上阀门）的唯一结局是**摘掉那颗键**、
   在站点那行时间上留一道虚下划并把原因写进宿主的悬浮说明，之后每秒复检不再建键；
   一台计时器都没找到（还没就绪）**不算**停不住，键留在原地不判死刑。
5. **真实用时用读、不用算**：悬浮说明里那个 `已用 HH:MM:SS` 直接取站点每秒在数的 `elapsed_time`，
   脚本不设第二只计时表（那只表交不上去，谁都不会看见，只会和站点那份打架）。

## 后果

- 交卷上报的用时**含暂停期间**。这是有意的取舍：它比净做题用时更真，代价是站点侧那份统计
  从此不表示"坐在题前的时间"。
- 这条不可逆的方向要说清：一旦习惯"用时含暂停"，再想要净做题用时就必须**写**站点的时间字段，
  而那被判据明令禁止（`gth_logic_test.js` 的 T33 那条 `miss(/\.(totalTime|elapsed_time|remainTime)\s*=(?!=)/)`）。
  想反悔只能走"脚本自己另设一只表来显示"，那与第 5 条冲突，不叫恢复原状。
- practice 练习模式那一页从此没有这颗键。如果站点将来给那一页加上到点交卷，本票的划界口径要跟着改，
  改的是那条 `freezablePage` 判据与 `AGENTS.md` 里「可暂停的定义」那一条，不是加一个开关。
- 停不住时少了一个"看得见但按不动"的入口，换来的是界面上不存在按下去不动的东西。
- 场景一里"人不在时被随机跳到别的板块"这件事仍然被挡着（板块时钟一起冻），但它是第 1 条的直接推论，
  不再是一项隐形的副作用——`AGENTS.md` 已把那条后果单独记下来。
- 与 `docs/adr/0003` 的关系：那一票按**交卷状态**划界（决定能不能记笔记），本票按**有没有后果**划界
  （决定有没有这颗键），两套划界在同一页上并存，交卷后本脚本主动把那块头部擦干净让给解析界面。
- **待真页面证（L2）**：阀门分母变小后 `阀门N/M` 的实际数字；那道虚下划会不会被站点或 bootstrap 的
  `text-decoration` 盖掉；`zhuanxiang` 上 `elapsed_time` 是否每秒真被站点写（静态 bundle 为证，运行时未证）；
  以及真链接里 `page_type` 到底出现在 `search` 还是 `hash`（本票两处都读，出现在哪一处都算命中）。
