# ADR 0007 — 逐题用时：记录在答题态那半，展示在专项解析页，单写者只读

- 状态：Accepted（2026-10-08 修订：记录器随两份脚本并入 `shangancun-exam-helper.user.js` 同一份文件，
  决策 1 / 3 / 4 里"两份脚本"那层作用域改判；新增决策 8 补材料组卷面的记账与展示口径）
- 日期：2026-10-07
- 相关：`docs/adr/0006`（暂停只管倒计时）、`docs/adr/0003`（做题页零注入）、`docs/adr/0005` 决策 13（解析页只做逐题小条）、`docs/adr/0008`（两份脚本合并）

## 背景

用户要的形状：交卷后的解析页上给一份**可展开**的列表——收起只看总用时，展开看**每一题**的用时，用于考后复盘；
本轮只做专项练习页（`zhuanxiang.html`），其它界面留后。

对着站点公开静态 bundle 复算（`gongan2_zhuanxiang.min.79ef825a.js` 72485 字节、
`gongan2_practice.min.e888d08a.js` 81354 字节，命中数可重算）：

1. **站点没有逐题用时**。交卷上报的答案体是 `user_answer.push({subject_id:data.id, answer:[…]})`——每题只带题号与选项；
   唯一的时间明细是 `$scope.detail_elapsed_time[val.name] = val.elapsed_time`，**键是板块名**，粒度到板块为止。
   模板里带 time 的绑定只有 `part_elapsed_time` / `part_total_time`。
2. 交卷那条分支 `if("finished"==status) return …, void $scope.showAnalysis();` **排在
   `$scope.detail_elapsed_time={}` 之前**——解析页这条路上那份板块用时根本不重建。
   所以"读站点已有的板块用时"在专项页既没有信息量（`partData` 初始化只有一个板块条目）也未必读得到。
3. 专项页**一屏一道题**（`ng-repeat="subjectObj in localStorage.currentPartData.subjectList"` 配
   `ng-if="localStorage.currentIndex == subjectObj.index"`），所以"这一秒属于哪道题"判得干净；
   practice 会随机跳板块、模考报告页是 swiper（DOM 里同时约 7 格），两边都有歧义——这是"先只做专项页"的结构理由，
   不只是排期。
   **2026-10-08 修正**：这条只对**非材料组**卷面成立。资料分析这一类卷面站点按 `material_id` 把题归成材料
   （20 题 → 4 个材料，每个 5 题），答题态一屏摊的是**整个材料**，`currentIndex` 只在**材料首题号**之间跳。
   那时"一屏"与"一题"不是一回事，见决策 8。
4. 分场键要用 `exam_id`：`submit_id=publicjs.getSearch().submit_id||""`（答题态可能是空串），
   而站点自己那套续答缓存就叫 `zhuanxiang_cache_key="zhuanxiang_cache"+exam_id`。

于是"要不要两种模式"这个问题在这里第二次被消解：数据不是站点给不给的问题，而是**谁来记**的问题。

## 决策

1. **记录器落在答题态那一半**（2026-10-07 时它是独立脚本「考试计时暂停」，2026-10-08 与助手并入同一份文件，
   仍是同一段代码）。它本来就是唯一跑在答题态的代码，所以不需要动 `docs/adr/0003`
   给错题助手画的「做题页零注入」红线——那条约束管的是笔记与划线入口，不是时钟。
2. **每秒把 1 秒记在当前那一个记账单位上**，键是站点自己的口径（`currentIndex == subjectObj.index` 那一道的 `id`）；
   **暂停期间的那一秒照样记在当前单位上**（2026-10-09 用户改判：这一份数据要的是真实用时，离开两分钟就是两分钟；
   旧口径「暂停单列、不从当前单位扣」已撤）；`paused` 仍然逐秒累计，但退成**只用于展示「其中暂停多久」的副表**，
   既不从各题里扣，也不再加进合计。认不出当前单位的那一秒进 `lost`，**不许猜给上一个单位**。
   非材料组卷面下一单位就是一道题；材料组卷面下一单位是一段材料，见决策 8。
3. **存储走这份记录器自己的键 `gth_qtime_<ctx>`，按 `exam_id` 分场**，不并进助手那个整库。
   理由（2026-10-08 改判后仍在）：并库要迁移老数据；这条记录**每 5 秒落盘一次**，塞进整库等于让
   `ADR-0004` 那套「只增映射」的合并每次带上一个高频桶；那个 store 的形状是冻结契约，不该为合并而变。
   落盘前同样重读磁盘并**逐字段取大合并**（只增），所以多标签并发谁都不丢，并进来的秒数记在 `merged` 里可见。
4. **展示侧只读那份键**（判据锁"不许出现 `setItem(QTIME_KEY)`"），写的人永远只有一个。
   两半各自现算 `CTX`（`location.pathname.split('/')[1] || 'mingshi'`）——2026-10-08 合并后它们在同一份文件里、
   不共享作用域，所以仍是两处定义；判据从"跨文件一字不差"改成"**同一份文件里两处一字不差**"。
   口径一错就是静默读不到。
5. **展示形状**（同日改过两次：折叠带 + 题干引文 → 站点蓝色头部 → **内容区右上角**，后者是用户 2026-10-07 定的）：
   专项页那个内滚盒子 `.question-box` 里放一个 `.gth-ztop` 容器，`position:absolute;top:12px;right:24px`、
   成员间距 `10px`、`z-index:6`；里面左边是用时入口 `本场做题用时 …（N 题）`，右边是逐题小条（笔记 / 复制题目 / 整理本题那一排）。
   浮窗与笔记浮窗同宽（`min(340px,72vw)`），一行只有**序号与用时**。浮窗常驻 DOM，可见性由 CSS 的
   `:hover` / `:focus-within` / `.on` 三种开法决定，点击只切 class、不重画整块。
   **题干引文与一切解释性文案按用户要求删掉**（"没列出来的题＝…"、"选中题干或解析里的文字即可划线"）。
   挂点为什么不能是站点蓝色头部：视觉上被裁、且压住站点自己的头部——判据现在直接禁止那份里出现这个名字。
   2026-10-08 两处改动：容器**去掉整条白底**（一条白带压在题干上不像原生），改成每项自带一层极淡的可读底；
   行标签在材料组卷面下是**区间**（`第 11–15 题`），标题的计数按覆盖到的题数据出（`（20 题 · 4 段材料）`）。
6. **这一场本机没有记录时不挂入口**，但在控制台说一句（`用时：场次 X 本机没有计时记录，这一页不挂用时入口`）——
   界面上一个字都不留，同时留一条查得到的痕："页面上什么都没有"有三种原因（旧版脚本 / 这一场没记录 /
   宿主没找到），不写这一句就只能靠截图猜。
7. **这是对 `docs/adr/0005` 决策 13 的一次公开例外**：那条写的是解析页"只做逐题小条，不重建视图"。
   本轮在专项解析页加了一条用时带，因为它承载的是这份脚本独有的数据（逐题计时只有跑在答题态的那份能记），
   放进错题页那套助手视图反而看不到。例外只到**专项练习页**为止，`mocks` 与 `analysis.html` 不受影响。
8. **材料组卷面按「一屏 = 一个记账单位」记账，单位就是材料**（2026-10-08 新增）。
   站点把这类卷面按 `material_id` 归成材料，答题态的导航只在材料首题号之间跳，一屏摊着该材料全部小题，
   **读题时间无法归属到某一小题**——按 ADR 同一条纪律（认不出就不许猜），不拆分、不均摊：
   记录端一个字不改（键天然落在材料首题的 `id` 上），展示端认出那一项带 `opts.length > 1` 就把标签写成区间
   `第 11–15 题`；逐题小条上材料内每题都显示这一份账，标签写 `本材料 04:49`（重复是"这一段都在算这条账"的信号，
   不是漏记）；入口上的计数按覆盖到的题数出（`（20 题 · 4 段材料）`），与卷面题数对得上。
   `opts` 是站点 `chuliZhijueSubject` 挂在每一项上的派生字段，拿不到时退回单题号显示，不报错。

## 后果

- 复盘只在**装上新版之后进行的场次**里有数据；已经做过的 506 题、49 道模考题补不回来。
  而现在**页面上没有任何地方解释"为什么没有这条入口"**——这是用户看完第一版之后明确选的取舍，
  原因只写进控制台那一行。
- 浮窗签名按**每题各几秒**算，不按总和：两笔同为 300 秒但分布不同的记录，内容不同就必须重画。
  第一版这里有一处重复定义（后定义的"按总和"那份胜出），已修，判据把两种情况都钉住。
- 恒等式仍是这套数据唯一的自证方式：**合计 = 各题之和 + 未归属**（暂停的秒数已在「各题之和」里，
  再把 `paused` 加一次就是双计——2026-10-09 随决策 2 一起改）；出数位置在计时那份那颗键的悬浮说明里。
  界面上的浮窗只给各题之和（按用户要求不带未归属）。
- 后台标签页里浏览器会节流 `setInterval`，所以我们的分摊与站点那份总时钟**同源一起变慢**；
  换来的是两边永远对得上账，代价是精确到秒的"挂后台时长"本脚本给不了。
- 材料组卷面（决策 8）不需要迁移：键本来就是材料首题的 `id`，**那一场已经记下的旧记录当场就能显示成区间行**。
  代价是展示依赖站点挂在每一项上的 `opts`；拿不到时退回单题号，界面上看起来仍是"只记了材料首题"。
- `practice` 考试模式与模考页这一轮都不记；将来要扩，先解决"这一秒属于哪道题"的归属歧义，
  不是先把 `isZyPage()` 改成通用判断。
- **待真页面证（L2）**：真专项页交卷态上 `currentPartData.subjectList` 是否还完整（顺序靠它，
  取不到时按题号升序兜底）；`exam_id` 在真链接里出现在 `search` 还是 `hash`（两处都读，出现在哪都算）；
  答题态点暂停时那一段是否真的记给了当前题（决策 2 于 2026-10-09 改成「暂停照样记在当前题头上」，
  这一条要重验的是它在真页面上的表现，不是它该不该这样记）；以及记录器每秒读一次 scope 会不会与站点
  自己的 `cacheAnswer()` 写盘互相拖慢（夹具里静置 5 秒的 childList 变更为 0，只证了渲染不循环）。
  2026-10-08 追加两条：站点是否给**每一项**都挂了 `opts`（材料组逐题小条上的「本材料」用时靠它；
  夹具里是我们自己造的 `opts`，证不到站点那份），以及材料组卷面的答题态是否真的只在材料首题号之间导航
  （依据是站点 bundle 里 `goSpecIndex(item.opts[0].index)`，没有在真页面上数过）。
